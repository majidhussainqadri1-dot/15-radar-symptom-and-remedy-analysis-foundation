# Contributing

1. Start from an issue or change record that names the requirement ID, canonical owner, data class, affected contracts, migration, rollback and acceptance evidence.
2. Never add diagnosis, prescription, potency, dosage, emergency-care or patient-record behavior to File 15.
3. Never copy a copyrighted repertory or unlicensed dataset.
4. Do not store raw credentials or patient-identifying information.
5. Keep private studies out of public search, AI, feeds, trends, analytics and logs.
6. Use `RSR_` PHP symbols, `rsr_` storage/hooks, versioned events and stable public IDs.
7. Preserve mobile-first, RTL, keyboard, focus, contrast, zoom and reduced-motion support.
8. Add or update tests and requirement traceability with every material change.
9. Run `bash scripts/build.sh` and correct every defect before opening a pull request.
10. Source merge does not authorize staging or production deployment.
